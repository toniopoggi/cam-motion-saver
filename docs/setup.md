# Google setup and first recording

Cam Motion Saver 0.5.14 uses each operator's own Google configuration.
Installing the APK does not supply an OAuth client or event subscription.

Before starting, read Google's [Device Access quick start](https://developers.google.com/nest/device-access/get-started)
and [registration requirements](https://developers.google.com/nest/device-access/registration).
Registration currently costs a one-time US$5. API access, quotas and any Cloud
charges belong to your Google projects, not to a Cam Motion Saver account.

## 1. Check camera and phone compatibility

Use Android 9 or newer on ARMv7 or ARM64. The current recorder receives
WebRTC/H.264. Check the protocol for your exact camera and its Nest/Home
migration state in Google's [device list](https://developers.google.com/nest/device-access/supported-devices).
RTSP-only support in Google's list does not make a device compatible with this build.

Set up the camera normally and keep both camera and recorder online.

## 2. Configure Google projects

1. Register in the Device Access Console using an eligible consumer Google account.
2. Create/configure a Google Cloud project and enable the Smart Device Management API.
3. Configure Google Auth Platform and an OAuth web client with the required
   SDM scope, following Google's current quick-start instructions.
4. Create a Device Access project associated with that OAuth client.
5. If you want optional Google event triggers, enable events for the Device
   Access project and note its published topic. Steps 6–8 are for that option.
6. Create a dedicated **pull** Pub/Sub subscription to that topic in your
   Cloud project. Do not select push delivery or an export subscription.
7. Create a dedicated service account and give it the subscription permissions
   needed to receive/acknowledge messages. Use the least privilege needed;
   the Pub/Sub Subscriber role on the subscription is the usual starting point.
   The app also checks subscription metadata; resolve any separate metadata
   permission failure shown in its diagnostics.
8. Obtain that service account's JSON credential for the recorder.
   Keep it private; it contains a private key.

The app's OAuth redirect URI and the console's authorized redirect URI must
match exactly. Inspect the `redirect_uri` in the authorization link generated by
the current APK and register that exact URI. Do not substitute an arbitrary
callback from another application or use this README as a source for a guessed URI.

## 3. Enter the configuration on the recording phone

Expand **Camera & Google settings**. Enter:

| Field | Meaning |
| --- | --- |
| Device Access project ID | The Device Access enterprise/project identifier, not the Google Cloud project ID |
| OAuth client ID / secret | The web client associated with that Device Access project |
| Camera device name | The full SDM device resource name for this authorized account/project |
| Pub/Sub subscription | Full resource path: `projects/PROJECT/subscriptions/SUBSCRIPTION` |
| Service account JSON | The private credential used to consume the pull subscription |

Save the configuration. Use **Authorize Google account** and sign in with an
account authorized for the camera. If multiple Google accounts are available,
check which account the browser selects.

After consent, return to Cam Motion Saver. If needed, expand **Complete Google
authorization**, paste the final redirect URL or code and select **Exchange
code**. Keep the resulting refresh token private.

SDM device identifiers can differ between authorizations/accounts. Use the
resource name returned for the current configuration; do not copy an old
account's camera ID and assume it is universal.

## 4. Verify the stream and motion paths separately

- **Verify Nest access:** confirms the device/API authorization path.
- Wait for a connected WebRTC stream and buffered video.
- Under **Live view & motion**, enable phone detection, choose sensitivity, and
  draw/save an area if you want to restrict detection. The default is the full image.
- Move within the area, then confirm an MP4 appears and plays; adjust sensitivity.
- If using Google events, enable that option and **Check subscription access**.
  Trigger motion and confirm raw messages arrive and a trigger is accepted.

A stream working does not prove Pub/Sub event delivery. A subscription check
passing does not prove Google has published a new event.

For the optional Google event path, use **Reconnect event delivery** if reauthorization changed the event setup,
then inspect the raw counters. It requests activation; it does not prove that
a subsequent motion event was delivered.

## 5. Choose recording and storage settings

**Motion clip duration** is 5–600 seconds after the trigger, plus available
pre-roll. Subsequent eligible triggers extend the deadline.

**Keep recordings for** accepts whole days, minimum/default 1. One day means
the last 24 hours. Seven means seven rolling days; 30 means 30 days, not a
calendar-month calculation. Cleanup runs at startup and about once per minute.

Changing retention does not restart the camera stream. Reducing retention
deletes older completed clips and their previews at the next cleanup.

## 6. Share the local gallery

Use **Share** on the recorder phone and copy the complete viewer link,
including its token. Open it on a device on the same trusted LAN.

The admin link is separate. Keep it private.
Use the numeric-IP fallback when local discovery fails.

## OAuth Testing versus Production

Google's [authorization troubleshooting](https://developers.google.com/nest/device-access/reference/errors/authorization)
documents the seven-day token problem. Google Cloud's OAuth publishing status
is separate from Device Access commercial certification.

Moving the OAuth consent screen to Production addresses the Testing-related
short token lifetime; reauthorize afterward if necessary. It does not make a
token permanent, expose your camera to every Google account, publish an APK or
approve a commercial recording integration. Other accounts would still need
to authorize their own devices.

Choose the status appropriate to your project and follow Google's current
verification guidance. Public distribution has additional constraints described
in the README; do not reuse a personal client as a shared hosted credential.
